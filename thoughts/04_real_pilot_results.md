## 设计
- 每个 item：~1600 字符 stdlib docstring prose + 6 个标识符（hex12 / sha16 / UUID / 路径 / IP:port / 6 位数）+ 1 句 codename（prose 可读性探针）。
- 三组，**视觉 token 完全相等**（`⌈w/28⌉×⌈h/28⌉`）：
  - **A uniform**：单一字号，按字符硬折行（标识符可能被切断）
  - **B nobreak**：同字号，按词折行（RQ2）
  - **C hazard**：按词折行；文本侧 regex 标出的 token 放大，prose 用剩余预算下最大字号（RQ1）
- 两个工作点：5px（19.6 字符/vtok，72 vtok）与 6px（13.9 字符/vtok，108 vtok），各 12 个不同 item（不同 seed）。
- **拉丁方**：3 个读者 × 12 张，每个读者每个 item 只见一次、arm 轮换；文件名打乱，读者不知道 arm；答案不在读者可见路径。

**第二轮结论**
1. **RQ1 在 N=42 下稳固**：4 个（读者 × 密度）格子 C−A 全部显著，+16 到 +52 点。
2. **C' 的 prose 下限没有用**：保住 prose 字号并没有让 codename 变好（Claude −0.10，MiniMax 0.00），却让标识符少了 13–24 点。→ **该缩的是 prose，该放大的是标识符；放大幅度很关键（12px ≫ 8–9px）。**
3. **anchors vs hazard 的 Pareto**：14 ch/vtok 时 C 达到 0.95–0.98，D 只多 +2/+6 点，却多花 **+70% token**。20 ch/vtok 时 C 不够（0.48–0.77），D 仍然必要。→ 方法 = **C 作默认，只在极高密度时叠加 anchors**。
4. **新发现：anchors 会伤害弱读者的 prose 读取**：MiniMax 在 D 组的 codename 比 C 组低 30 点（5px）和 13 点（6px），CI 不跨 0。合理解释：文本 sidecar 抢走注意力，模型更少看图里的 prose。C 没有这个副作用。
5. **prose 代价的位置变了**：第一轮看到 MiniMax 5px 有 prose 下降，第二轮合并后消失（−0.02）；反而 Claude 5px 出现 −0.14 的趋势（CI 跨 0）。5px 时 C 的 prose 字号和 A 一样（都是 5px），所以如果代价是真的，来源不是字号，而可能是混排行高或大字号标识符抢注意力。需要专门实验（见 03）。
6. **协议偏差**：Claude 读者 run2_s6/r3 用 Bash heredoc 写输出（违反"只用 Write"），未读取其他文件，数据完整性不受影响；另有读者把 sidecar 里的误报（`4/3`）主动剔除——不影响评分（只看真标识符）。

- **CD（arm E）**：C 渲染 + 只对渲染后仍 <10px 的标识符附文本 anchor（10px 阈值来自第二轮）。

**第三轮结论**
1. **RQ1 第三次复现**，并推广到**真实数据**（+17 / +24 点，CI 不跨 0）。
2. **prose 代价在合成数据上基本不存在**（4 格中 3 格 CI 跨 0；Claude 6px −0.09 临界），**但在真实数据上显著**（−0.13 / −0.21）。原因很可能是：真实数据里被标记的 token 是整条清单行（路径+哈希+大小，~100 字符），放大后吃掉大量版面，prose 被压到 5px 且行数增加。→ **方法修正：只放大高熵子串（哈希本身），不放大整个空白分隔 token。**
3. **anchors 让弱读者"不再看图"**：MiniMax 一旦拿到文本 sidecar，prose 探针暴跌（5px：0.81→0.28/0.31；6px：0.86→0.62/0.72），两轮均复现、CI 不跨 0；Claude 不受影响。这是对 R-or-R anchor sidecar 的一个重要新告诫。
4. **CD 组合价值有限**：14 ch/vtok 时 CD≈C（+0–2 点）却多 24% 成本；20 ch/vtok 时 CD 等价于 D（所有标识符都 <10px，全部附 anchor）。Pareto 拐点就是 C。
5. **静默错误不是 prompt 逼出来的**：允许"[unreadable]"后模型几乎不用它，静默错误率不降——模型**不知道自己读错了**。这正是"静默"的含义，也说明不能指望模型自报不确定性，只能靠渲染端预防（C）或校验（check-and-retry）。

## 解读
1. **RQ1 成立（真实 VLM）**：同等视觉 token 下，把分辨率挪给高风险 span，精确率 0.32→0.78（5px）、0.79→0.99（6px），静默错误 0.50→0.15、0.15→0.00。CI 均不跨 0，且没有任何 item 变差。
2. **prose 基本没有被牺牲**（MiniMax 5px 例外，见上）：C 组 prose 缩到 5px，但 codename 准确率反而略高（0.83/0.92 vs 0.75/0.67）。原因之一：放大后的标识符不再与周边文字混淆。（N=12，差异不显著，只能说"未见代价"。）
3. **RQ2 信号弱**：nobreak 方向为正（+4/+8 点），但 CI 跨 0。单独不足以成文，可作为 RQ1 方法里的一个组件（C 已经含 nobreak）。
4. 5px 时 C 的标识符只能放到 6–7px（行高约束），仍拿到 +46 点——说明**小幅放大就够**，存在很大的效率空间。

## 局限（写论文前必须补）
- 读者已有 2 家（Claude 子代理、MiniMax-M3）；论文最好再加 1 家开源（如 Qwen-VL）。
- 每格 N=12 item / 72 标识符；pilot 规模。
- 没有实际运行 anchors 组（成本按 2 字符/token 估算；精确率按论文应接近 1）。
- 文本 token 成本是估算（无 tokenizer）；视觉 token 用官方公式，未经 count_tokens 核验。
- 子代理"读者"可能与 API 直接调用有差异（Read 工具是否重采样图片未知）；但三组走同一通道，比较是公平的。
- 读者自述会"把看不清的组补齐到应有长度"——这正是静默错误机制，但也说明 prompt 措辞（"给出最佳猜测"）会影响 silent 率；应加一组允许"[unreadable]"的 prompt 做稳健性检查。
